# 03 — 补写「换 idol 时旧动态如何处理」的 ADR

**What to build:** 一份记录下来的决策，说明用户更换守护对象后旧 idol 的动态数据发生了什么，以及为什么这样选。

代码事实上已经做出了选择：更换守护对象时只改写用户身上的 idol 关联，动态数据全部保留，前端按当前 idol 过滤展示。这与 PRD 中标注的推荐方案一致，但从未被记录为决策。没有记录的结果是，下一个读到界面文案「换人后旧动态会清空」的人会以为这是个 bug 并去「修复」它。

对应 PRD 开放问题 #3。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent
