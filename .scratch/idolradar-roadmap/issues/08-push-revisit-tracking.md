# 08 — 推送回访上报（服务端）

**What to build:** 能够回答「收到推送的用户里，有多少真的点开了小程序」——即 PRD 成功指标中的「推送到达后回访率」。

目前投递侧已经记录了「发出去了」，但没有任何数据记录「用户点开了」。缺的正是这一半。

推送落地链路里已经带有可识别该次推送的标识，落地页在启动时也已经读取了它，因此只需在落地时向服务端上报一次即可闭合。上报做在服务端而非客户端埋点：本项目规划为多端产品，服务端上报天然跨端复用，未来 app 客户端无需重复实现。

**Blocked by:** 01 — 申请订阅消息模板并接通生产链路

**Status:** ready-for-agent

- [ ] 用户从推送落地时，服务端记录一次可归因到该次投递的回访
- [ ] 同一次投递被重复打开时不重复计数，或能区分首次与重复
- [ ] 非推送来源的正常打开不被误计为回访
- [ ] 上报字段遵守 PRD 合规要求，不包含用户身份敏感信息
- [ ] 能够按时间区间统计出回访率
